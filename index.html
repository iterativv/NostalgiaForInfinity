Freqtrade Bot Report

In-browser port of tools/bot_report.py — exports a redacted JSON telemetry report from a running freqtrade REST API, so strategy developers can review how a strategy behaves in production. Everything runs locally in this browser tab.

No server sees your data

This page is a single static file with all logic embedded. It makes no network call to any server except the freqtrade API URL you enter below. There is no CDN, no fonts, no analytics, no uploads, nothing stored: the report is generated in your browser and saved straight to your disk. Closing the tab discards everything, including your credentials.

You can verify this: press F12 to open your browser DevTools, switch to the Network tab, and reload this page. You will see zero requests until you click Export report, and afterwards only requests to your bot's address from the form. The page also ships a strict Content-Security-Policy, so the browser itself blocks anything else.

Setup — letting this page talk to your bot
  1. Enable the freqtrade REST API ("api_server": {"enabled": true, …} with username/password) in your bot's config.
  2. Browsers enforce CORS: add this page's exact origin (no trailing slash) — https://YOURNAME.github.io — to CORS_origins in the same api_server block and restart the bot: 
    "api_server": {
    "enabled": true,
    "listen_ip_address": "127.0.0.1",
    "listen_port": 8080,
    "username": "freqtrader",
    "password": "…",
    "CORS_origins": ["https://YOURNAME.github.io"]
}
    Without this entry the bot answers without the CORS headers browsers require, and every request from this page fails before reaching freqtrade.
  3. If this page is served over HTTPS and your bot is plain HTTP, browsers usually allow http://127.0.0.1 / http://localhost as an exception (Chrome may additionally ask for a local-network permission). Remote bots over plain HTTP will be blocked as mixed content — put them behind a TLS reverse proxy. Certificates must be valid; this page cannot skip verification (there is no --no-verify-tls in a browser).
What gets redacted?

Credentials and keys (any field whose name contains key, secret, token, password, chat, webhook or credential; the whole ccxt_config objects), exchange order/account identifiers, absolute money values (balances, stakes, costs, absolute PnL, funding fees, drawdown water marks) and personal/machine-specific values (bot name, local paths). Numeric redaction is fail-closed: a number is kept only when its key is recognized as safe, so fields freqtrade adds in the future are hidden until reviewed. Scale-invariant relative ratios are computed before redaction so the report stays useful without revealing the account size. Full field reference: tools/bot_report.md.

Single-file tool, no build step, no dependencies. Read-only: it only ever issues GET requests to /api/v1/*. Styling: shadcn-classless (MIT, embedded — no external stylesheet is loaded).
